# SmartVintaAwesomeKit v0.6 release report

## Product understanding

The release continues the developer workflow improvements introduced in v0.5. The primary friction addressed is safe evolution after generation: developers need to know what the generator owns, whether managed files have drifted, why an API request failed, and whether production secrets are safe.

## Implemented improvements

### Scaffold inspection

- SHA-256 hashes for generator-managed files.
- Resource metadata in `.smartvinta.json`.
- Read-only `inspect` command.
- Human-readable and JSON reports.
- `--check` mode for CI with non-zero exit on drift.

### Stable API errors

- Stable codes for common HTTP failures.
- Field-level validation paths and messages.
- Request IDs in error bodies and response headers.
- Internal exceptions remain hidden from clients.
- Legacy exception-handler mapping keys retained for compatibility.

### Production safety

- Production doctor verifies `.env` presence.
- Placeholder and short JWT secrets are rejected.
- Secret values are never emitted.

### Resource lifecycle

- `add-resource` records fields, generated route, and test paths.
- Managed-file checksums update after resource generation.
- Later inspection distinguishes expected generated state from drift.

## Requirements

### Must

- Inspection must never change project files.
- CI check mode must return non-zero for missing or modified managed files.
- Error responses must include code, message, fields, and request ID.
- Validation errors must preserve field paths.
- Production diagnostics must reject placeholder JWT secrets.
- Resource generation must update scaffold metadata atomically with its output.

### Should

- Existing public exception-handler mapping keys should remain available.
- Human and JSON CLI output must represent the same state.
- Developer-created unmanaged files must not be classified as drift.

### Deferred

- Three-way upgrade and automatic merge support.
- Database-persisted generated resources.
- Complete database-backed authentication preset.
- Redis-backed distributed rate limiting.

## Implementation details

- `api.py` now defines an error schema and handlers for FastAPI HTTP and request-validation exceptions.
- `cli.py` generates checksum-aware manifests, provides `inspect`, and expands production doctor checks.
- `resource_cli.py` records generated resource metadata and updated checksums.
- `test_v060_release.py` contains release acceptance tests.
